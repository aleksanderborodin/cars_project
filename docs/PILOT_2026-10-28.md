# First implemented development experiment

2026-10-28. [Index](../README.md) · [Research log](RESEARCH_LOG.md) ·
[Status](STATUS.md) · [Campaign ledger](../configs/campaigns/development-pilot-2026-10-28.json)

The modular prediction → candidate simulation → action → replanning loop now
runs. This is an adaptive development pilot, not a frozen paper experiment.
The revised controller has not established superiority: its mean return improves
over a fixed candidate controller, but the interval includes zero and completion
is lower. Final standard test and legacy unseen/hard sets remain untouched.

## What actually ran

- Official standard CarRacing dynamics/reward/termination, 1000 native frames,
  continuous steering/gas/brake, four frames per control decision.
- Local observation: a 61×61 road occupancy mask sampled at 1 m spacing inside a
  30 m circle, visibility mask, body forward/lateral velocity, yaw rate and previous
  action. This is an ideal geometry sensor, not native pixels or full-map input.
- Ordinary ridge regression fits one-step observed ego dynamics. The model also
  integrates predicted motion. It has no wheel-state history or uncertainty ensemble.
- Road prediction is a constant terminal-tangent extension, not a learned road
  distribution. Candidate behavior is parameterized by target speed and steering
  gain, with 21 combinations simulated for 20 decisions (1.6 seconds).
- Search penalizes predicted departures, lateral displacement/slip and travel
  beyond the observed footprint, and rewards progress. Execute only the first
  0.08 s and replan. This is a finite grid, not CEM or exhaustive control search.

The new namespace manifest reserves 200 development, 200 calibration and 500 final
test identities, with a separate reproducible training namespace. Test identities
are represented by a commitment and unavailable through the development API.
The historical audit covers eight documented legacy training configurations; it
does not certify arbitrary undocumented manual resets. No legacy dataset was reused.

For the revised search over three independent collection/training seeds, mean
return is **687.0**. Relative to the fixed speed-60 controller, the mean difference
is **+73.6**, with an exploratory 95% crossed model/paired-track bootstrap interval
of **[-24.2, +180.2]**. All three trained models complete 20% of tracks versus the
fixed controller's 30%. This does not satisfy the proposed completion guardrail
or establish a reliable performance advantage. The interval is not adjusted for
adaptive development/model selection and is limited by three trained instances
and twenty tracks.

## Why the design changed during the pilot

The first four tracks gave an overly favorable impression of search. The complete
20-track development pass showed that it underperformed. We retained the early
results rather than presenting only the favorable subset.

Public ego/action logs showed a distribution mismatch: about 99% of forward-speed
observations in the original collection were below 50, while search often chose
70–90 targets. First-step error on conservative development data was much smaller
than persistence (forward-speed RMSE 0.748 versus 3.841 m/s), yet rollouts and
aggressive driving remained unreliable. Low one-step error was insufficient.

The follow-up crossed collection coverage with candidate grids:

- Conservative collection: 30 episodes, 30,000 native frames.
- Mixed collection: cycle local pursuit and fixed-speed 40/60/80 controllers,
  with action noise; 30 episodes per seed, respectively 28,169 / 28,664 / 27,926
  native frames. These are equal episode caps, not exactly equal frame budgets.
- Wider speeds: 30/40/50/60/70/80/90. Bounded speeds: 20/25/30/35/40/45/50.
  Both use steering gains 0.8/1/1.2 and 420 model transitions per decision.
  The bounded grid changes lower-speed options too; it is not a pure upper-cap test.

The existing 8-track diagnostic collection uses 8,000 frames; a mixed-policy
development collection adds 7,699 frames. These diagnostics are development data,
not another hidden test. Fitting/checkpoint reload and multi-step diagnostics are
saved with each dynamics artifact. No real user-only oracle ranking was consumed
in these design choices or analyses.

A reconstruction bug was also fixed: partially observed cross-sections near the
circular sensor edge could create a spurious bend. The original smoke artifacts
and a synthetic regression test preserve the history and failure mechanism.

## Learning and native-input checks

The local recurrent run used 100,349 actual native frames, including a recorded
349-frame rollout overshoot, and zero expert/hidden-truth labels. It used a small
CNN/LSTM, fixed input scales, ordinary Gaussian exploration, and no reward
normalization. It is a custom adapter smoke/pilot, not a faithful reproduction.

The native RGB protocol completed a 2,048-frame training smoke test and a two-track
development evaluation. Initial and recurrent actions match after checkpoint
reload. This verifies integration only, not visual competitiveness. Native inputs
contain the official image and previous action, without numeric ego state or map.

The RL Zoo recurrent-CarRacing configuration at upstream commit
`61956d90d9f8ac126043ed4024efa12a462d97e1` uses materially different preprocessing,
exploration, network/training choices and budget. Audit it before calling the
baseline competitive: [pinned upstream configuration](https://github.com/DLR-RM/rl-baselines3-zoo/blob/61956d90d9f8ac126043ed4024efa12a462d97e1/hyperparams/ppo_lstm.yml).
Its published recipe is not silently substituted into our matched-information
table, and neither that reproduction nor TD-MPC2/DreamerV3/Valdi has run here.

New recurrent runs now save weights, optimizer state, random states and training
sampler state. Continuation is tested with **fresh episodes**, not identical
mid-episode physics. Earlier pilot checkpoints without complete RNG snapshots
remain valid for inference but are explicitly rejected for state-preserving
continuation.

## User-only ranking monitor

The user's metric is implemented as a separate online process. It audits 12
prescheduled states across four development tracks and 21 frozen candidate action
sequences per state. Simulator resets and deterministic prefix replay replace
unsafe Box2D cloning. Public resource counts are 252 resets, 100,800 replay frames
and 20,160 candidate frames; these are separate diagnostic costs, not training data.

**Real ranks, oracle returns, regrets and correlations remain user-only.** They
are absent from this report and were not opened by the assistant. The ignored
HTML/JSON report lives under `private_diagnostics/devpilot_20261028_user_monitor/`.
Only public technical status and ordinary driving logs were checked. All chosen
actions, rewards and permitted observations were bit-identical across the 20
episodes with and without the monitor. The monitored repeat is excluded from
the statistical analysis; it is not another independently trained run.

## What this justifies next

1. Improve control/model robustness using ordinary permitted training/development
   evidence. The user-only oracle monitor is excluded from that feedback loop.
2. Diagnose the same planner with declared full-map information, separately from
   the existing expert. This remains a proposal, not a completed experiment.
3. Establish a competitive learned baseline and original-protocol reproduction
   before expensive multi-seed headline comparisons.
4. Add scenario/world distributions or adaptive behavior proposals only with
   controlled comparisons. The user's Bayesian idea remains a future option.

The first implementation/development experiment is complete. The competitive
control/baseline gates for the large paper campaign remain open. No SOTA, novel
algorithm, calibrated-road-belief, safety or sim-to-real result follows.
